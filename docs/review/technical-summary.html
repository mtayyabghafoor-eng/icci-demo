ICCI Control Dashboard

Technical summary for the review team · November 2026

A private web system for the admin team of the Islamic Cultural Centre of Ireland, Clonskeagh. It covers inventory and assets, people and Garda vetting, training, policies and sign-offs, vehicles and renewals, with rota, maintenance, a library, expenses and a monthly report to follow. It runs in a normal web browser on a PC or phone; there is nothing to install. Only named admins can sign in.

The demo at icci-demo.vercel.app runs on a separate database filled with made-up data only. A review account can be provided to your team on request.

How it is built

  • Website: Next.js 16 with TypeScript (React).
  • Database, sign-in and file storage: Supabase (PostgreSQL 17).
  • Hosting: Vercel. Site and database both in the EU (Frankfurt today; Ireland can be chosen for the live system).
  • Three separate copies: development and staging (made-up data only) and production.
  • Mainstream, open technologies: any experienced Next.js or PostgreSQL developer can maintain it.

Sign-in and access

  • Two-factor sign-in (authenticator app) for every account, no exceptions.
  • Passwords of at least 12 characters; automatic sign-out after 15 minutes idle.
  • Roles: Super Admin, Centre Admin, Finance, and a limited Library role.
  • No staff or volunteer logins, by design, to keep the number of accounts small.

Security: enforced in the database, not only on screen

RuleHow it is enforced
Each role sees and changes only what it shouldRow-level security on every table. Automated tests prove that each role, and a signed-out visitor, is refused what it should not do.
Nobody approves their own entryChecked by the database itself on every approval (stock corrections, asset changes, stocktakes, policy publishing).
Nothing is deletedNo hard deletes anywhere. Records are deactivated, or corrected by a new linked entry.
Every change is traceableAn append-only audit log records who did what, and when. It cannot be edited.
Stock figures cannot be overwrittenQuantities are worked out from movements and counts, so every number can be traced back.
Database changes are controlledEvery change is a numbered migration file under version control; nothing is changed by hand.
Keys stay secretKeys live outside the code. The website holds only the public key; the database's master key is never sent to it.
Labels reveal nothingA QR label holds only a link with its number. Scanning one without signing in shows nothing.

A full security review of the codebase was carried out after the first stage, and its fixes are in place.

Data protection

  • Collects the minimum. It never stores vetting disclosures, medical details, identity documents, home addresses, bank or card numbers, or PPS numbers.
  • Hosted in the EU, with the providers' standard data processing agreements.
  • A written agreement and data protection paperwork with ICCI come before any real data is entered.
  • The prototype has never held real personal data.

Quality

  • Over 1,100 automated checks run before every change is accepted: type checks, code checks, unit tests, database permission tests, and browser tests on PC and phone screens.
  • Every change is tried on the staging copy before it goes live.
  • Readable colour contrast (WCAG AA), keyboard use and a skip link are tested.
  • Built with AI-assisted development (Claude Code); every change reviewed and tested before acceptance.

Ownership, handover and continuity

  • All service accounts are registered with a project email so they can be transferred to ICCI.
  • The Centre owns its data at all times and can export it in standard formats (CSV).
  • A handover pack (specification, operating guide, service list, incident log) lets another developer take over.
  • A named backup developer on a small retainer covers absence or problems beyond the main developer.
  • Daily backups on the live system; a previous version of the site can be restored in minutes.
